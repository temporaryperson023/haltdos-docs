Integrating a Vercel App with Haltdos Enterprise WAF

Haltdos · WAF · Listener Setup  ·  Last updated May 2026  ·  10 min read

This guide walks through onboarding a Vercel-hosted application onto the Haltdos Enterprise WAF — creating a listener, configuring server groups, setting the host header correctly, and pointing DNS to the WAF so all traffic is inspected and protected before reaching Vercel.

Key Information About Your Vercel App

Before starting, we resolved the Vercel app's DNS to get its actual backend IPs. Vercel is a multi-tenant platform — it does not use a static IP. The IPs rotate frequently (TTL of only 86 seconds), and Vercel routes traffic to the correct app using the Host header, not the IP alone.

bash — haltdos@haltdos-Kartik
haltdos@haltdos-Kartik:~$ dig server-blue-new.vercel.app ;; QUESTION SECTION: ;server-blue-new.vercel.app. IN A   ;; ANSWER SECTION: server-blue-new.vercel.app. 86 IN A 216.198.79.67 server-blue-new.vercel.app. 86 IN A 64.29.17.67   ;; Query time: 0 msec ;; TTL: 86 seconds (rotates frequently)

Three critical facts to keep in mind throughout this setup:

  • Vercel backend IPs: 216.198.79.67 and 64.29.17.67 — both on port 443
  • Vercel requires HTTPS — SSL must be enabled on the Server Group
  • The Host Header must be set to server-blue-new.vercel.app — without this Vercel returns a 404 regardless of the IP

Step-by-Step Setup

1

Create the Listener

Apps → WAF → Listeners → Add Listener

🗂 Apps › WAF › Listeners › Add Listener

The Listener is the entry point — it defines what domain the WAF listens on and where to forward traffic. Fill in the fields as follows:

Field Value Notes
Domain / Virtual IP myapp.yourdomain.com Your own domain — this is what users will hit in their browser
Service Type HTTP Select HTTP — HTTPS is handled at the port level in a later step
Origin Servers 216.198.79.67:443
64.29.17.67:443		 Add both Vercel IPs. Haltdos will load balance across them — matching how Vercel distributes traffic

Click Save Changes.

💡 Adding both IPs ensures that if Vercel serves traffic from either node, the WAF will correctly forward to it. Vercel's anycast routing uses both IPs simultaneously.

2

Create a Server Group

WAF → Listeners → [your listener] → Load Balancing → Server Groups

🗂 WAF › Listeners › [listener] › Load Balancing › Server Groups › Add Server Group

Server Groups define how the WAF connects to the backend origin (Vercel). SSL must be enabled here because Vercel only accepts HTTPS connections.

Field Value Notes
Group Name vercel-backend Any descriptive name — used for identification only
SSL ✅ Enabled Mandatory — Vercel rejects plain HTTP connections on port 443
Connection Timeout 30 seconds Vercel apps can have cold-start delays — 30s gives enough headroom
Read Timeout 30 seconds Time to wait for a response from Vercel after the connection is established

Click Save Changes.

⚠️ If SSL is not enabled on the Server Group, the WAF will try to connect to Vercel over plain HTTP on port 443, which Vercel will reject — causing all requests to fail with a connection error.

3

Add Both Vercel IPs as Servers

Server Groups → Servers → Add Server (repeat twice)

🗂 Server Groups › Servers › Add Server

Add each Vercel IP as a separate server entry inside the Server Group. Do this step twice — once per IP.

Server 1

Field Value Notes
Server 216.198.79.67 First Vercel backend IP
Port 443 Vercel only serves on HTTPS port 443
DNS Record Type A Record Direct IP — no DNS lookup needed
Remote ✅ True Mark as remote since Vercel is an external server
Mode Ready Puts the server in active rotation immediately

Server 2

Field Value Notes
Server 64.29.17.67 Second Vercel backend IP
Port 443 Vercel only serves on HTTPS port 443
DNS Record Type A Record Direct IP — no DNS lookup needed
Remote ✅ True Mark as remote since Vercel is an external server
Mode Ready Puts the server in active rotation immediately

Click Save Changes after each server.

⚠️ Note on IP rotation: Vercel's IPs have a TTL of only 86 seconds and can rotate over time. If traffic starts failing in the future, re-run dig server-blue-new.vercel.app and update the server IPs. For a more stable long-term setup, use the hostname server-blue-new.vercel.app in the Server field with DNS Record Type set to ANY — Haltdos will resolve it dynamically.

4

Set the Host Header ⚠️ Most Critical Step

WAF → Listener → Settings → Operational

🗂 WAF › Listener › Settings › Operational

Find the Host Header field and set it to exactly:

Host Header value to enter
server-blue-new.vercel.app

Click Save Changes.

🚨 This is the single most important setting in this entire guide. Vercel is a shared multi-tenant platform — hundreds of apps share the same IPs. The only way Vercel knows which app to serve is by reading the Host header on each request. If this is not set, Vercel will return a 404 for every request regardless of which IP you connect to. The WAF must inject this header on every request it proxies to Vercel.

5

Configure the Listener Port & SSL

WAF → Listener → Settings → Operational → Add Port

🗂 WAF › Listener › Settings › Operational › Add Port

Still in Operational Settings, add the HTTPS port so the WAF accepts incoming traffic from users over a secure connection.

Field Value Notes
Port 443 Standard HTTPS port — users connect here
Protocol HTTPS Enables SSL termination at the WAF
SSL Enabled ✅ True The WAF will present your domain's SSL certificate to users

Optionally, also add port 80 with SSL disabled to catch plain HTTP traffic — you can then configure an HTTP→HTTPS redirect rule to send all users to the secure version.

Click Save Changes.

6

Upload Your SSL Certificate

WAF → Listener → SSL Management

🗂 WAF › Listener › SSL Management

Upload the SSL certificate for your own domain (e.g. myapp.yourdomain.com). This is the certificate the WAF will present to users who connect to your domain.

💡 This certificate is completely separate from Vercel's own SSL certificate. Vercel's cert covers *.vercel.app — it is used on the backend connection from WAF to Vercel (Step 2). Your certificate covers your custom domain and is used on the frontend connection from the user to the WAF.

You need two certificates in total:

  • Frontend cert (uploaded here) — for myapp.yourdomain.com — presented to end users
  • Backend cert — Vercel's own *.vercel.app cert — handled automatically when SSL is enabled on the Server Group
7

Update DNS to Point to the WAF

Your DNS provider → A Record → WAF public IP

The final step is to update your domain's DNS so that myapp.yourdomain.com resolves to the Haltdos WAF's public IP — not directly to Vercel.

Record Type Name Value
A myapp (or @ for root) Your Haltdos WAF's public IP address

✅ Once DNS propagates, all traffic to your domain will flow through the WAF before reaching Vercel. The WAF will inspect, filter, and protect every request.

⚠️ DNS propagation can take anywhere from a few minutes to 48 hours depending on your DNS provider and TTL settings. Use dig myapp.yourdomain.com to verify the A record has updated to the WAF IP.

Common Issues & Fixes

Symptom Cause Fix
Vercel returns 404 Host Header not set or incorrect Go to Listener → Operational Settings → set Host Header to exactly server-blue-new.vercel.app
SSL handshake error (WAF → Vercel) SSL not enabled on the Server Group Edit the Server Group and enable SSL — Vercel only accepts HTTPS on port 443
Connection timeout Vercel cold-start delay or IP has rotated Increase Connection/Read Timeout to 30s. Re-run dig and update Server IPs if they've rotated
WAF blocks legitimate requests Security rules flagging app traffic patterns Check Security Profiles and Rules — whitelist specific patterns or put the listener in monitor-only mode initially
Vercel rate-limits the WAF All traffic appears to Vercel as one source IP Configure Vercel's firewall to whitelist your WAF's public IP address
App works but images/assets fail Asset URLs hardcoded to vercel.app domain Check your app's base URL configuration — assets should use relative URLs or your custom domain
