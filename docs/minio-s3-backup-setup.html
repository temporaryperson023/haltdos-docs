MinIO S3 Backup Setup for Haltdos

Haltdos · Configuration  ·  Rocky Linux 9  ·  Last updated June 2026  ·  15 min read

This guide walks through setting up a self-hosted MinIO object storage server on Rocky Linux 9 (VMware) and connecting it to the Haltdos platform as an S3-compatible backup destination.

Architecture

🛡 Haltdos Platform
172.16.0.56
→
S3 backup · HTTPS · port 9000
↓
Domain: minio.haltdos.local → 172.16.0.38
🗄️ MinIO Server
172.16.0.38
S3 API :9000 · Web Console :9001

⚠️ All commands in Part 1 run on the MinIO VM (172.16.0.38). Commands in Part 2 run on the Haltdos VM (172.16.0.56). Replace IPs with your actual values.

Important Notes Before You Start

Topic Detail
HTTPS is mandatory Haltdos strictly requires a valid HTTPS URL for the S3 endpoint. Plain http:// will be rejected with "Invalid URL specified".
Private IPs are blocked Haltdos blocks RFC1918 private IP ranges (172.16.x.x, 10.x.x.x, 192.168.x.x) in the S3 URL field. You must use a domain name instead.
Password special characters Avoid # in passwords set via shell — the shell treats # as a comment. Always wrap passwords containing # in double quotes in shell commands and config files.
SELinux on Rocky Linux 9 Downloaded binaries need to be relabeled with chcon -t bin_t otherwise systemd cannot execute them and MinIO will fail to start with a Permission denied error.

Part 1 — MinIO Setup on Rocky Linux 9

1

Update System & Install Dependencies

sudo dnf update -y
sudo dnf install -y wget curl
2

Download & Install MinIO Binary

wget https://dl.min.io/server/minio/release/linux-amd64/minio
sudo cp minio /usr/local/bin/
sudo chmod +x /usr/local/bin/minio

# Fix SELinux label — required on Rocky Linux 9
sudo chcon -t bin_t /usr/local/bin/minio

🚨 Do not skip the SELinux relabel. Without chcon -t bin_t, systemd will fail to start MinIO with status=203/EXEC and "Permission denied" — even though the file has execute permissions.

3

Create MinIO User & Data Directory

sudo groupadd -r minio-user
sudo useradd -m -r -g minio-user minio-user

sudo mkdir -p /data/minio
sudo chown -R minio-user:minio-user /data/minio

💡 For production, mount a dedicated XFS-formatted disk at /data/minio. For a test lab, the directory on the root disk works fine.

4

Create the Environment Config File

Create /etc/default/minio with your credentials:

sudo vim /etc/default/minio

Paste this content — note the password is quoted to handle special characters:

MINIO_VOLUMES="/data/minio"
MINIO_OPTS="--address :9000 --console-address :9001"
MINIO_ROOT_USER=minioadmin
MINIO_ROOT_PASSWORD="Haltdos#123"
sudo chown minio-user:minio-user /etc/default/minio
sudo chmod 600 /etc/default/minio

⚠️ Always wrap the password value in double quotes in the config file. Without quotes, the # character and everything after it is treated as a comment — MinIO will read a truncated password and authentication will fail.

5

Create the systemd Service File

sudo vim /etc/systemd/system/minio.service

Paste this content:

[Unit]
Description=MinIO Object Storage
Wants=network-online.target
After=network-online.target
AssertFileIsExecutable=/usr/local/bin/minio

[Service]
WorkingDirectory=/usr/local/
User=minio-user
Group=minio-user
EnvironmentFile=-/etc/default/minio
ExecStart=/usr/local/bin/minio server $MINIO_OPTS $MINIO_VOLUMES
Restart=always
LimitNOFILE=65536
TimeoutStopSec=infinity
SendSIGKILL=no

[Install]
WantedBy=multi-user.target
sudo systemctl daemon-reload
sudo systemctl enable --now minio.service
sudo systemctl status minio.service

Confirm these lines appear in the status output:

bash — root@localhost (MinIO VM)
Active: active (running) API: http://172.16.0.38:9000 http://127.0.0.1:9000 WebUI: http://172.16.0.38:9001 http://127.0.0.1:9001
6

Open Firewall Ports

sudo firewall-cmd --permanent --add-port=9000/tcp
sudo firewall-cmd --permanent --add-port=9001/tcp
sudo firewall-cmd --reload

Both commands should return success.

7

Install MinIO Client (mc) & Create Bucket + User

Download the MinIO client and apply SELinux label:

curl -sLO https://dl.min.io/client/mc/release/linux-amd64/mc
sudo chmod +x mc
sudo chcon -t bin_t mc
sudo mv mc /usr/local/bin/

Set an alias, create the backup bucket, and create a dedicated user for Haltdos:

# Set alias — password in quotes to handle special characters
mc alias set myminio http://localhost:9000 minioadmin "Haltdos#123"

# Create the backup bucket
mc mb myminio/haltdos-backup

# Create dedicated user for Haltdos
mc admin user add myminio haltdos-user "HaltdosSecret@123"

# Assign read/write policy
mc admin policy attach myminio readwrite --user haltdos-user

# Verify
mc ls myminio/
mc admin user list myminio

Expected output from mc ls myminio/:

bash — root@localhost (MinIO VM)
[2026-06-18 06:19:57 EDT] 0B haltdos-backup/

⚠️ If mc alias set fails with a signature mismatch error, check that the password in /etc/default/minio is correctly quoted. Restart MinIO after fixing it with sudo systemctl restart minio.service and try the alias command again.

8

Generate HTTPS Certificate for MinIO

Haltdos requires HTTPS. Generate a self-signed certificate using MinIO's certgen tool. Include both the IP and the domain name you'll use:

# Download certgen
wget https://github.com/minio/certgen/releases/latest/download/certgen-linux-amd64
chmod +x certgen-linux-amd64

# Generate cert — include IP, localhost, and the domain name
./certgen-linux-amd64 --host "127.0.0.1,localhost,172.16.0.38,minio.haltdos.local"

# Create cert directory and move certs
sudo mkdir -p /home/minio-user/.minio/certs
sudo mv public.crt /home/minio-user/.minio/certs/
sudo mv private.key /home/minio-user/.minio/certs/
sudo chown -R minio-user:minio-user /home/minio-user/.minio/

# Restart MinIO — it auto-detects certs and switches to HTTPS
sudo systemctl restart minio.service
sleep 3
sudo systemctl status minio.service

After restart, the status output should show https:// instead of http://:

bash — root@localhost (MinIO VM)
API: https://172.16.0.38:9000 https://127.0.0.1:9000 WebUI: https://172.16.0.38:9001 https://127.0.0.1:9001

💡 Why include the domain name in the cert? Haltdos blocks private IPs like 172.16.x.x in the S3 URL field. We use a domain name (minio.haltdos.local) instead — the cert must include this domain in its Subject Alternative Names (SAN) or the SSL handshake will fail.

Part 2 — Configure the Haltdos Machine

9

Add Domain Entry on Haltdos VM

Run these commands on the Haltdos machine (172.16.0.56). Add a local DNS entry so the domain resolves to the MinIO VM:

echo "172.16.0.38  minio.haltdos.local" | sudo tee -a /etc/hosts

Verify it resolves:

ping minio.haltdos.local
10

Trust the MinIO Self-Signed Certificate

Copy the MinIO cert from the MinIO VM and install it as a trusted CA on the Haltdos machine:

# Copy cert from MinIO VM
scp root@172.16.0.38:/home/minio-user/.minio/certs/public.crt /tmp/minio-selfsigned.crt

# Install as trusted CA
sudo cp /tmp/minio-selfsigned.crt /etc/pki/ca-trust/source/anchors/minio-selfsigned.crt
sudo update-ca-trust

Verify the cert is trusted — this must return 200 OK without the -k flag:

curl -v https://minio.haltdos.local:9000/minio/health/live

Confirm you see both of these lines in the output:

bash — root@testname (Haltdos VM)
* subjectAltName: host "minio.haltdos.local" matched cert's "minio.haltdos.local" * SSL certificate verify ok. < HTTP/1.1 200 OK Server: MinIO

✅ SSL certificate verify ok and HTTP/1.1 200 OK without the -k flag confirms the certificate is fully trusted on the Haltdos machine. Haltdos UI will now accept the URL.

Part 3 — Configure Haltdos Backup Settings

11

Fill in the S3 Backup Settings in Haltdos UI

Navigate to:

🗂 System › Instance › [Select Instance] › Settings › Backup Setting

Fill in the fields exactly as shown:

Field Value Notes
S3 Backup Enabled Enabled Toggle on to reveal S3 fields
S3 Region us-east-1 MinIO accepts any region string — use this as a dummy value
S3 Bucket Name haltdos-backup The bucket created in Step 7
S3 Path logs Subdirectory inside the bucket where backups are stored
S3 Access Key haltdos-user The dedicated MinIO user created in Step 7
S3 Secret Key HaltdosSecret@123 Password for the haltdos-user account
S3 URL https://minio.haltdos.local:9000 Must use domain name — private IPs are blocked by Haltdos

Click Save Changes, then click Backup Now to trigger an immediate backup.

🚨 Do not use a raw IP address in the S3 URL field. Haltdos blocks all RFC1918 private IP ranges. The URL https://172.16.0.38:9000 will be rejected. You must use the domain https://minio.haltdos.local:9000 that you configured in Step 9.

12

Verify Backup Files Arrived in MinIO

Run this on the MinIO VM after clicking Backup Now:

mc ls --recursive myminio/haltdos-backup/ --insecure

If backup files landed you will see entries like:

bash — root@localhost (MinIO VM)
[2026-06-18 12:00:01 EDT] 1.2MB logs/backup-20260618.tar.gz

✅ Backup files present in the bucket means the full integration is working end-to-end.

Troubleshooting

Symptom Cause Fix
"Invalid URL specified" in Haltdos UI Using http:// instead of https:// MinIO must run with TLS. Complete Step 8 to generate the cert.
Private IP rejected in S3 URL field Haltdos blocks RFC1918 ranges Use domain name minio.haltdos.local via /etc/hosts entry.
MinIO fails to start — status=203/EXEC SELinux blocking binary execution Run sudo chcon -t bin_t /usr/local/bin/minio and restart.
mc alias fails — signature mismatch Password truncated by # in config file Edit /etc/default/minio and wrap password in double quotes. Restart MinIO.
SSL cert domain mismatch error Cert generated without domain name SAN Regenerate cert with --host including the domain. Repeat Steps 8 and 10.
Bucket empty after Backup Now Offloader not picking up S3 config yet Wait for the offloader cycle (runs every 5 minutes) or check journalctl -u offloader.service.
