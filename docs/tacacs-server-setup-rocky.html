TACACS+ Server Setup on Rocky Linux

Haltdos · Configuration  ·  Rocky Linux / RHEL  ·  Last updated June 2026  ·  10 min read

This guide walks through setting up a TACACS+ authentication server on Rocky Linux using Docker. By the end you will have a running TACACS+ container with live log monitoring accessible directly from the host machine.

⚠️ All commands in this guide must be run as root or with sudo. The user home directory used throughout is /home/haltdos — replace this with your actual username if different.

Prerequisites

  • Rocky Linux VM (or RHEL / CentOS equivalent)
  • Internet access on the VM to pull Docker and clone the repo
  • A user account — this guide uses haltdos as the username

Step 1 — Install Docker

Install Docker and enable it to start on boot:

sudo dnf install -y yum-utils
sudo yum-config-manager --add-repo https://download.docker.com/linux/centos/docker-ce.repo
sudo dnf install -y docker-ce docker-ce-cli containerd.io
sudo systemctl enable --now docker

Verify Docker is running:

docker --version
sudo systemctl status docker

Step 2 — Clone the TACACS+ Docker Image Repo

Navigate to the haltdos user home directory and clone the TACACS+ Docker image repository:

cd /home/haltdos
git clone https://github.com/llima3000/tacplus_image
cd tacplus_image

⚠️ Important path note: Always use the full path /home/haltdos/tacplus_image/ in all subsequent commands. Do NOT use $(whoami) when running as root — it resolves to /home/root which does not exist and will cause mount errors.

Step 3 — Build the Docker Image

docker build --no-cache -t tacplus .

This will take a few minutes. Once complete you should see Successfully tagged tacplus:latest.

Step 4 — Create the TACACS+ Configuration File

Create the tac_plus.conf file with your users and groups. The config below includes example users — update the usernames and passwords to match your requirements:

cat > /home/haltdos/tacplus_image/tac_plus.conf << 'EOF'
key = tacacs123

accounting file = /var/log/tac_plus.log

group = netadmin {
    default service = permit
    service = exec {
        priv-lvl = 15
    }
}

user = tacadmin {
    member = netadmin
    login    = cleartext "tacadmin123"
    pap      = cleartext "tacadmin123"
    chap     = cleartext "tacadmin123"
}

user = chap_user {
    member = netadmin
    chap   = cleartext "Chap@123"
}

user = chap_user1 {
    member = netadmin
    chap   = cleartext "Chap@1234"
}
EOF

Verify the file was created correctly:

cat /home/haltdos/tacplus_image/tac_plus.conf

💡 About the accounting file path: The path must be set to /var/log/tac_plus.log — this is the actual log file name inside the container. Using tac_plus_acct.log will result in a file-not-found error.

Config Fields Explained

Field Value Description
key tacacs123 Shared secret between the TACACS+ server and Haltdos. Must match exactly in both places.
accounting file /var/log/tac_plus.log Path inside the container where authentication logs are written.
group = netadmin — Defines a group with full service permit and privilege level 15.
login = cleartext Password string Password for ASCII/login authentication.
pap = cleartext Password string Password for PAP authentication.
chap = cleartext Password string Password for CHAP authentication — this is what you use to log into Haltdos UI.
member = netadmin Group name Assigns the user to the netadmin group defined above.

Step 5 — Open Firewall Port 49

TACACS+ uses port 49. Open it permanently in the firewall:

sudo firewall-cmd --permanent --add-port=49/tcp
sudo firewall-cmd --reload

Both commands should return success.

Step 6 — Run the TACACS+ Container

Start the container with the config file and log directory mounted from the host:

docker run -d \
  --name tacplus \
  -p 49:49 \
  -v /home/haltdos/tacplus_image/tac_plus.conf:/etc/tacacs+/tac_plus.conf \
  -v /var/log/tacacs:/var/log \
  tacplus

The two -v flags do the following:

Flag What it mounts Why
-v ...tac_plus.conf:/etc/tacacs+/tac_plus.conf Your config file into the container Container reads your users and settings from this file
-v /var/log/tacacs:/var/log Host directory into container's /var/log Logs written inside the container appear on the host at /var/log/tacacs/

Step 7 — Verify the Container is Running

docker ps | grep tacplus

You should see output like this:

bash — root@localhost
root@localhost:~# docker ps | grep tacplus ac5d1efabacd tacplus "/bin/sh -c '/usr/sb…" 6 seconds ago Up 5 seconds 0.0.0.0:49->49/tcp tacplus

Also confirm port 49 is listening:

ss -tunlp | grep 49
bash — root@localhost
tcp LISTEN 0 4096 0.0.0.0:49 0.0.0.0:* users:(("docker-proxy",pid=20329,fd=8)) tcp LISTEN 0 4096 [::]:49 [::]:* users:(("docker-proxy",pid=20334,fd=8))

✅ Both IPs 0.0.0.0:49 and [::]:49 listening means the server is accepting connections on all interfaces.

Step 8 — View Live Authentication Logs

Since the log directory is mounted to the host, you can tail logs directly without going inside the container:

tail -f /var/log/tacacs/tac_plus.log

When the server starts and when users authenticate, you will see entries like this:

bash — root@localhost — /var/log/tacacs/tac_plus.log
Sat Jun 6 08:24:48 2026 [7]: Reading config Sat Jun 6 08:24:48 2026 [7]: Version F4.0.4.27a Initialized 1 Sat Jun 6 08:24:48 2026 [7]: tac_plus server F4.0.4.27a starting Sat Jun 6 08:24:48 2026 [7]: socket FD 4 AF 2 Sat Jun 6 08:30:12 2026 [7]: connect from 172.16.0.65 Sat Jun 6 08:30:12 2026 [7]: login query for 'chap_user' from 172.16.0.65 accepted

Alternatively, view logs from inside the container:

docker exec -it tacplus tail -f /var/log/tac_plus.log

Step 9 — Enable Auto-Restart on Reboot

By default the container will not start automatically after a VM reboot. Fix this with:

docker update --restart=always tacplus

✅ Your TACACS+ server will now automatically restart whenever the Rocky Linux VM reboots.

Day-to-Day Operations

Common commands you'll use regularly:

Task Command
Check if container is running docker ps | grep tacplus
View live logs from host tail -f /var/log/tacacs/tac_plus.log
Add or edit a user vi /home/haltdos/tacplus_image/tac_plus.conf
Apply config changes docker restart tacplus
Stop the container docker stop tacplus
Remove and re-run container docker rm -f tacplus then re-run the docker run command from Step 6
View all log files in container docker exec -it tacplus ls /var/log/

⚠️ Always run docker rm -f tacplus before re-running docker run — otherwise Docker will error with "name already in use". After editing tac_plus.conf, always run docker restart tacplus to apply the changes.
